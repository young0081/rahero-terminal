## Context

本变更要复刻《鸣潮》星炬学院的"拉海洛终端"，目标是一套高度还原《鸣潮》科技 HUD 美学的**交互界面**，面向 C 端用户，原生运行于 Windows / Linux / Android 三平台。

关键事实约束：

- **游戏内并未对该终端做完整界面设定**：拉海洛终端整体作为外壳在游戏中只是设定层面的存在，终端外壳（布局、导航、状态栏、特效）没有官方完整稿，需要我们**基于《鸣潮》整体科技美学自行设计**。但其中被拆分到游戏内的子功能（尤其"飞讯"）**有真实可见的游戏内界面**，这部分将参考玩家实机截图进行高度还原，而非自由发挥。
- **功能取材于游戏内被拆分出来的终端能力**：游戏把终端的部分能力（如"飞讯"消息系统）直接做成了玩家可用的玩法。本项目把这些能力收敛回"终端"这一外壳下重新组织（飞讯、势力资料库等）。
- **素材为运行时下载，不入仓库**：本项目开源。受版权的图标 / logo / 图片等素材**不提交进仓库**，改为应用首次运行时从库街区（Kuro 官方社区）按清单下载到本地缓存目录，下载后离线复用（详见决策 9 与 asset-provisioning spec）。用户本机 `鸣潮息屏/`（各势力 / 角色动态图标：60 帧 MP4、GIF、PNG 序列、AE 工程）与 `refs/frames/`（抽帧参考图）仅为**开发期确认风格的本地参考**，不随仓库分发。已通过抽帧确认配色：深空联合开机为纯黑底 + 白银线条（#f0f0f0 系）；星炬学院标志为青柠绿（#b4f064 系）+ 蓝色（#6078d8 系）点缀。
- **开发期网络检索不可用**：本会话内 WebSearch / WebFetch / fetch 均被网络策略阻断，开发期"参考资料"来源为用户本地素材 + 抽帧分析。注意这只影响**开发期检索**，不影响最终应用——成品在终端用户机器上联网即可从库街区下载素材。

环境现状（已实测）：

- 已安装：git 2.54.0；OpenJDK 21.0.10 (Temurin LTS)；Android SDK（默认路径 `%LOCALAPPDATA%\Android\Sdk`，含 build-tools / platforms / licenses）；Visual Studio 2022（含 Windows 桌面 C++ 构建链）。
- 未安装：Flutter SDK / Dart SDK。按全局规则，Flutter 的安装与环境配置由我在骨架阶段自行完成，用户无需手动安装任何东西。
- Linux 平台产物：本机装有 Ubuntu，可在其上执行 `flutter build linux` 产出 Linux 原生二进制。Windows 端负责 Windows + Android 构建与开发，Linux 二进制在本机 Ubuntu 侧产出。代码层仍严格避免平台独占 API、桌面适配走统一抽象，保证三端一致可构建。

## Goals / Non-Goals

### Goals

- 一套 Dart 代码库，覆盖 Windows / Linux / Android 三平台的原生构建与运行。
- 高度还原《鸣潮》科技 HUD 的**视觉与交互观感**：深色背景、青柠绿辉光、棱角几何边框、扫描线 / 故障 / 数据流氛围特效、打字机文案、动态图标循环播放。
- 完整的开机序列：深空联合动态图标开机动画 + 终端自检打字机文案 + 转场进主界面，含资源缺失降级与可跳过。
- 终端外壳 + 两个功能模块：飞讯（messaging，参考实机截图还原）、势力资料库（faction-archive），以及它们的本地数据持久化。
- 响应式布局（桌面多栏 / 移动单栏 + 抽屉）与双输入（鼠标键盘 / 触控）适配。
- 素材运行时从库街区按清单下载到本地缓存、离线复用、下载失败降级到占位，并按需加载控制内存。

### Non-Goals

- 不做后端服务 / 账号系统 / 联网对战。全应用为**纯本地、单机**应用，无任何自有服务端、无用户数据上传、无密钥。唯一的网络行为是首次运行时从库街区下载素材（只读拉取，不上传任何数据），下载后即可完全离线运行。
- 不还原《鸣潮》的实际游戏玩法（战斗、养成、地图）。仅还原"终端"这一信息 / 交互外壳及其内含的轻功能。
- 不追求逐帧像素级复刻某张官方界面截图（因为不存在完整官方稿）；以"风格高度一致 + 自洽设计"为准。
- 不实现飞讯的真实即时通讯；飞讯是**剧情脚本驱动**的本地消息流，非真实网络聊天。
- 首版不做 macOS / iOS / Web 平台（虽然 Flutter 技术上支持，但不在本变更范围）。

## Decisions

### 决策 1：技术栈选 Flutter (Dart)

**选择 Flutter** 作为唯一技术栈，理由：

- 一套代码原生编译到 Windows / Linux / Android，正好满足"一套代码全平台"诉求。
- 自绘渲染引擎（Skia/Impeller），对自定义 HUD 视觉、CustomPainter 绘制几何边框 / 扫描线 / 辉光、着色器特效支持好，能精确还原科技美学，不受系统原生控件样式限制。
- 动画系统（AnimationController / Tween / Rive 可选）成熟，适合大量过渡与氛围动效。
- 视频 / 序列帧 / GIF 播放有成熟插件生态。

**未选** 的替代方案及原因：

- Electron / Tauri（Web 技术栈）：Android 端支持弱（Tauri 移动端尚不成熟），Electron 体积大且无原生 Android。
- React Native：桌面端（Windows/Linux）支持为社区分支，成熟度与一致性不如 Flutter 官方三端。
- 原生分别开发（C++/Kotlin 各写一套）：违背"一套代码"诉求，成本高。

### 决策 2：状态管理用 Riverpod

采用 **Riverpod**（hooks_riverpod / flutter_riverpod）做状态管理与依赖注入：

- 编译期安全、可测试、不依赖 BuildContext 取状态，适合跨模块共享主题、会话数据、未读角标等全局状态。
- Provider 粒度可控，氛围特效 / 时钟等高频更新状态可隔离，避免无谓重建。

替代 setState（仅页面内局部用）/ Bloc（样板偏多）/ GetX（约定过多、可测试性差）。

### 决策 3：媒体播放分类型处理（统一抽象 `DynamicIcon`）

素材有三种形态：60 帧 MP4、GIF、PNG 序列帧。定义统一组件 `DynamicIconView`，按资源类型选择渲染后端：

- **MP4**：用 `video_player` 插件循环播放（桌面端经 `media_kit` / `video_player` 平台实现；Android 用原生 ExoPlayer 后端）。为统一三端表现，桌面端优先 **`media_kit`**（对 Windows/Linux 桌面视频支持更完善），Android 用 `video_player`。组件内做平台分发。
- **GIF**：用 `Image.asset`（Flutter 原生支持 GIF 动图）。
- **PNG 序列**：用 `AnimationController` 驱动帧索引，逐帧 `Image.file` 切换；序列帧目录与帧率写入素材清单。

媒体文件来源统一为**本地缓存目录**（由 asset-provisioning 在首次运行时下载，见决策 9），`DynamicIconView` 按素材清单解析出的缓存路径用 `Image.file` / `File`-based 视频源加载，而非 `Image.asset` 读打包资源。仅占位图标（素材缺失时的降级图）作为轻量内置资源随包。

开机动画（深空联合带文字）优先用 MP4，失败降级到序列帧 / GIF，再失败降级到内置静态占位标志图（满足 boot-sequence 的"资源缺失降级"场景，也覆盖素材尚未下载完成的情况）。

### 决策 4：本地持久化用 Hive

飞讯会话进度、已读状态、用户设置（特效开关、主题）用 **Hive**（纯 Dart、跨三端一致、无需原生 SQLite 依赖、读写轻量）持久化到应用文档目录。

- 飞讯剧情脚本（消息节点 / 分支）作为**只读资源**（JSON / Dart 数据）随包打包；用户进度（读到哪、选了哪个分支、已读标记）才写入 Hive。
- 替代 SQLite（对本场景过重）/ SharedPreferences（不适合结构化会话数据）。

### 决策 5：主题系统集中令牌化

建立单一 `AppTheme` / 设计令牌（design tokens）来源：颜色（背景黑、青柠绿 #b4f064、蓝 #6078d8、白银 #f0f0f0、辉光色）、字体（科技等宽 / 无衬线，中文回退字体随包）、边框几何参数、辉光强度、间距栅格。所有模块只从主题取值，保证 terminal-shell 要求的"全局视觉一致"。

- 字体：英文 / 数字用等宽科技字体，中文需随包打包一款可商用免费中文字体（如思源黑体子集），避免不同平台系统字体差异导致观感不一致。具体字体在 Open Questions 中确认许可后定稿。

### 决策 6：氛围特效用 CustomPainter + Shader，且可降级

扫描线 / 故障 / 数据流 / 噪点用叠加层实现：

- 扫描线、几何边框、辉光：`CustomPainter` 绘制；辉光用 `BoxShadow` / `ImageFiltered` 模糊。
- 故障（glitch）/ 噪点：可用 `fragment shader`（Flutter 的 `.frag` 着色器）或周期性 `CustomPainter` 重绘。
- **降级策略**：监测帧率 / 提供设置开关，低性能或用户关闭时停用 shader 与高频重绘，仅保留静态边框配色（满足 terminal-shell 与 platform-adaptation 的降级场景）。特效层独立于交互层，绝不拦截点击 / 影响可读性（`IgnorePointer`）。

### 决策 7：响应式与双输入统一在外壳层处理

- 用 `LayoutBuilder` + 断点（宽度阈值）切换桌面多栏 / 移动单栏 + 抽屉布局；布局切换通过保留同一状态树（Riverpod）保证"不丢状态"。
- 交互元素统一封装：桌面端加 `MouseRegion` 悬停态 + 键盘 `Shortcuts/Actions`；触控端保证最小点击热区（≥48dp）。同一套 widget 同时满足两端，不分叉两套代码。

### 决策 8：项目结构按 feature 分层

```
lib/
  main.dart
  app/            # App 根、路由、主题装配
  core/           # 主题令牌、常量、工具、媒体抽象(DynamicIconView)、持久化(Hive封装)、特效层
                  # + 素材服务(asset-provisioning: 清单解析/下载器/缓存路径解析/校验)
  features/
    boot/         # 开机序列(动画+自检文案+转场)
    provisioning/ # 首次运行素材下载界面(进度/失败重试/离线降级)
    shell/        # 终端外壳(状态栏+导航+内容容器)
    feixun/       # 飞讯(联系人/会话/消息流/分支/角标/持久化)
    archive/      # 势力资料库(列表/详情/检索分类)
  data/           # 只读资源数据模型(势力条目、飞讯剧情脚本)
assets/
  manifest/       # 素材清单(asset_manifest.json: id/来源URL/缓存路径/类型/校验)，随包
  placeholders/   # 占位图标(素材缺失/下载失败时的降级图)，随包
  fonts/          # 可商用免费字体，随包
  scripts/        # 飞讯剧情脚本JSON(占位先行)，随包
# 注意：受版权的动态图标(mp4/gif/png序列)不入仓库，运行时下载到平台缓存目录
```

### 决策 9：素材运行时下载 + 本地缓存（asset-provisioning）

本项目开源，受版权的图标 / logo / 图片素材不入库，改为应用首次运行时从库街区下载并缓存。架构如下：

- **素材清单（manifest）**：仓库内置 `assets/manifest/asset_manifest.json`，逐项记录素材的 `id`、来源 URL、目标缓存相对路径、类型（mp4/gif/png_seq/image）、校验信息（大小 / 哈希）。清单是下载行为的唯一真相来源，新增 / 替换素材只改清单。
- **缓存目录**：用 `path_provider` 取各平台规范目录——桌面用 application support 目录、Android 用应用专属外部 / 内部缓存目录——在其下建统一子目录（如 `rahero_assets/`）。三端用同一套相对路径逻辑解析，`DynamicIconView` 据此 `Image.file` 加载。缓存目录绝不指向仓库目录。
- **下载器**：启动时比对清单与缓存，仅拉取缺失 / 校验失败项（增量）；逐项下载到临时文件、校验通过再原子改名落盘，校验失败删除重下。下载过程有进度 UI（当前项 / 总体百分比）。
- **失败与离线降级**：单项失败用内置占位图标顶替并记录待重试，**绝不崩溃、绝不阻断进入应用**；全程无网络则提示素材暂不可用、以占位形态进入，联网后从设置"重新下载素材"补全。
- **缓存管理**：设置内可查看占用、清理缓存；清理后下次启动重新进入下载流程。

下载界面作为 `features/provisioning/`，在开机序列前置或并行展示；已缓存完整则直接跳过，无网络开销。该决策对应 asset-provisioning spec 的四条需求。

### 决策 10：飞讯按实机截图还原，内容占位先行

游戏内"飞讯"有真实可见界面，故飞讯模块的**视觉与布局以玩家实机截图为还原基准**（联系人列表样式、会话气泡、消息流、推送提醒的排布与配色尽量贴合截图），而非自由设计——这是与终端外壳（自洽设计）的关键区别。

- **内容占位先行**：飞讯对话脚本（角色、对话文本、分支）与势力资料库简介文案，先以《鸣潮》风格化的**示例性占位内容**跑通机制与界面，结构上预留替换位，后续可整体替换为正式内容（满足全局"先占位后补充"）。
- 占位脚本以 JSON 随包（`assets/scripts/`），替换内容不改代码、只换数据。

每个 feature 完成即可独立验证，符合全局规则的"模块化开发、错误隔离、分阶段交付"。

- **风险：三端构建环境分散。**  
  Windows 端构建 Windows + Android，Linux 二进制需在本机 Ubuntu 上构建，两处需各自跑通工具链。缓解：代码层严格避免平台独占 API、桌面适配走统一抽象；先在 Windows 跑通 Windows + Android 实测，再在 Ubuntu 执行 `flutter build linux` 产出 Linux 产物；三端共用同一份代码，差异仅在构建命令。

- **风险：库街区素材下载不稳定 / 链接失效。**  
  素材运行时从库街区拉取，存在链接变更、限流、网络不可达。缓解：清单驱动 + 校验 + 增量重试；单项失败降级到内置占位图、不阻断应用；提供手动"重新下载"入口；清单与 URL 集中维护，链接失效只改清单不改代码。终端用户全程无网络时也能以占位形态进入并使用核心交互。

- **风险：桌面端视频播放插件兼容性。**  
  `video_player` 在 Windows/Linux 桌面历史上支持不一。缓解：桌面端采用 `media_kit`（社区成熟、桌面三平台一致），Android 用官方 `video_player`，在 `DynamicIconView` 内做平台分发并提供序列帧 / GIF 降级路径，降低单一插件失败的影响面。

- **风险：大量动态图标一次性加载导致内存 / 体积失控。**  
  缓解：资料库按需加载（列表用缩略 / 首帧静帧，进入详情才播放完整动图）、离开释放控制器；资源压缩（MP4 转码合适码率、PNG 序列按需保留）；按势力分目录、可按需打包。满足 platform-adaptation 的体积 / 内存场景。

- **风险：着色器特效在低端 Android 掉帧。**  
  缓解：默认中等强度，提供"性能模式"开关 + 自动降级；特效层 `IgnorePointer` 不影响交互；可读性优先。

- **风险：字体 / 素材版权与可商用性。**  
  缓解：中文字体选可商用免费字体并做子集；游戏素材为还原用途，于 README 标注素材来源与非商用 / 致敬性质（见 Open Questions）。

- **Trade-off：自行设计终端界面 vs 还原度。**  
  因无官方完整稿，界面为自洽设计。取舍是优先"风格一致 + 交互沉浸"，而非"与某张官方图逐像素一致"（该图并不存在）。

## Migration Plan

本项目为全新创建，无既有代码迁移；"迁移"指从零搭建到可交付的推进顺序，遵循全局规则"先骨架验证、再逐模块填充、每步自验证"。

1. **环境准备（我执行，用户零操作）**：下载并安装 Flutter SDK，配置 PATH，`flutter config` 指向已装 Android SDK 与 VS 2022 桌面构建链，`flutter doctor` 排错至 Windows + Android 通过；启用 windows / android desktop 支持。本机 Ubuntu 侧另装 Flutter + Linux 桌面构建依赖，供产出 Linux 二进制。
2. **骨架**：`flutter create` 生成三端工程骨架，加入依赖（riverpod、hive、media_kit/video_player、go_router、path_provider、http/dio 等），配置 `assets`（manifest / placeholders / fonts / scripts），写好素材清单初稿，先跑通空应用在 Windows 与 Android 启动。**此处先验证空壳可运行再继续。**
3. **核心层**：实现主题令牌、`DynamicIconView` 媒体抽象（从缓存目录 `Image.file` 加载）、Hive 封装、氛围特效层、响应式 / 双输入基础组件。
4. **素材服务与下载界面（asset-provisioning）**：实现清单解析、缓存路径解析、增量下载器 + 校验、占位降级、下载进度与重试 UI、缓存管理；单独验证首次下载 / 已缓存跳过 / 离线降级 / 重新下载四条路径。
5. **开机序列模块**：接入深空联合动态图标 + 自检打字机 + 转场 + 降级 / 跳过；与素材下载界面衔接（未缓存先下载、已缓存直接开机）；单独验证。
6. **终端外壳模块**：状态栏 + 导航 + 内容容器 + 主题应用 + 特效叠加 + 响应式布局；单独验证。
