## Context

飞讯聊天已实现文本 / 表情的收发与本地持久化（`ChatLog` + Hive），但属于"能用"阶段：输入栏与气泡为基础样式，表情消息存在显示不全，新气泡瞬间出现无过渡，且整条链路假定"发送即成功"，没有任何网络态概念。

当前没有真实的飞讯后端——对话来自占位脚本（`feixun_scripts.json`），用户消息只是本地追加。但本次要求"考虑网络波动下的收发加载态"，因此设计需要在**没有真实网络**的前提下，建立一套可演示、且未来能无缝接入真实网络的发送 / 接收状态架构。

约束：三端（Windows / Linux / Android）表现一致；不引入新第三方依赖（用 Flutter 内置动画）；新增的消息状态字段必须向后兼容已持久化的旧数据。

## Goals / Non-Goals

**Goals:**
- 输入栏与气泡的视觉精修，提升可读性与《鸣潮》终端美学还原度。
- 彻底修复表情显示不完整（表情栏与气泡内表情均完整、等比、不被裁剪）。
- 新气泡出现带过渡动画（淡入 + 轻微缩放 / 上移）。
- 建立消息状态模型（发送中 / 已送达 / 失败）与"接收中"指示，配套加载动画与失败重试。

**Non-Goals:**
- 不实现真实飞讯服务器 / 网络协议（无后端）；仅建立状态架构 + 可配置的模拟延迟来演示加载态。
- 不改动联系人列表、推送角标等非聊天界面部分。
- 不引入消息撤回 / 编辑 / 已读回执等新功能。

## Decisions

### 1. 消息状态模型：在 `FeixunMessage` 增加可选 `status` 字段
为消息引入发送态：`sending`（发送中）、`sent`（已送达 / 默认）、`failed`（发送失败）。字段可选，缺省视为 `sent`。
- **为什么**：加载态与失败重试都需要每条消息携带状态；可选 + 缺省 `sent` 保证旧持久化数据（无该字段）反序列化后仍正确显示，满足向后兼容约束。
- **持久化策略**：只持久化"终态"消息（`sent`）。`sending` / `failed` 不写入或写入后在成功时改写——避免重启后残留"永久发送中"的幽灵消息。
- **备选**：单独的状态映射表（messageId → status）。否决：与消息生命周期割裂，重启对齐复杂。

### 2. 无后端下的网络态：可注入的 `MessageTransport` 抽象 + 模拟实现
定义一个发送/接收的传输接口，当前提供"模拟传输"实现（带可配置延迟与可选失败率），未来替换为真实网络实现即可，UI 与状态机不变。
- **为什么**：需求要"考虑网络波动"，但无真实服务器。抽象让加载态 / 失败 / 重试是真实的状态流转而非假动画，且为接入真实飞讯后端预留唯一改动点。
- **默认行为**：模拟传输默认成功、延迟很短，不干扰正常体验；加载动画在延迟窗口内自然呈现。失败率默认 0，可在设置 / 调试开关下调高用于演示。
- **备选**：直接在 UI 里写 `Future.delayed` 假延迟。否决：散落各处、不可测、无法演进为真实网络。

### 3. 气泡出现动画：进入过渡 + "接收中"打字指示
- 新气泡用进入动画（淡入 + 轻微上移 / 缩放），通过对列表新增项做一次性 `TweenAnimationBuilder` 实现。
- 对方"接收中"用独立的打字指示气泡（三点跳动），到达后替换为真实气泡。
- 用户"发送中"气泡显示小转圈 / 半透明，转为 `sent` 后落定；`failed` 显示重试按钮。
- **为什么**：内置动画零依赖、三端一致；打字指示是飞讯原界面既有的呈现语汇（与现有 spec"打字 / 淡入动画"要求一致）。

### 4. 表情完整呈现：约束盒 + 等比 contain + 统一基线尺寸
表情栏格子与气泡内表情统一用固定尺寸的约束盒 + `BoxFit.contain`，文字字形用居中且字号随盒缩放，杜绝裁剪 / 溢出 / 尺寸不一。
- **为什么**：当前显示不全源于盒尺寸与内容尺寸不匹配（字形行高 / 贴图比例）。统一基线尺寸 + contain 是最稳妥的修复。

## Risks / Trade-offs

- **模拟传输被误当成真实网络** → 在代码与 spec 中明确标注为占位实现，失败率默认 0；文案不暗示真实联网。
- **"发送中 / 失败"消息的持久化语义** → 只持久化终态；重启时 `sending` 不恢复为发送中。若失败消息需保留以便重试，单独标注其持久化规则，避免幽灵态。
- **动画在 Android 低端机掉帧** → 动画短（≤250ms）、轻量（透明度 + 位移），避免布局抖动；列表用稳定 key 防止误判新项重放动画。
- **新增 `status` 字段破坏旧数据** → 字段可选 + 缺省 `sent`，并在反序列化处容错；新增序列化往返测试覆盖"无 status 字段"的旧数据。
- **打字指示与逐条推进的现有 spec 重叠** → 本次以"接收加载态"复用并细化既有"打字 / 淡入动画"要求，不与之冲突。
