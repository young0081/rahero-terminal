## Why

飞讯聊天的收发已经能用，但交互观感与健壮性还有明显短板：输入框与气泡样式较粗糙、表情发出后会显示不全、消息气泡出现时没有动画、且完全没有考虑网络波动——收发消息缺少加载态与加载动画，弱网或离线时用户无从感知消息是否在发送 / 接收中。本次聚焦把飞讯聊天打磨到"顺手、完整、对网络波动有反馈"的程度。

## What Changes

- 优化聊天文本输入框：更贴合终端美学的样式、合理的内边距 / 圆角 / 占位提示、多行扩展与发送键的视觉与交互细节。
- 优化聊天气泡：气泡尺寸、留白、配色、对齐与时间戳排布的精修，提升可读性与还原度。
- 修复表情显示不完整：表情消息与表情栏中的贴图 / 字形需完整呈现（不被裁剪、不溢出、尺寸一致）。
- 新增消息气泡出现动画：用户发送与对方到达的新气泡以淡入 / 缩放 / 滑入等过渡出现，而非瞬间跳出。
- 新增收发加载态与气泡加载动画：考虑网络波动，发送中 / 接收中显示加载占位气泡与动画（如打字指示、转圈），并处理成功 / 失败 / 重试的状态反馈。

## Capabilities

### New Capabilities
（无 — 本次为既有飞讯能力的体验精修，不引入新能力）

### Modified Capabilities
- `feixun-messaging`: 修订"对话会话视图"与"消息流与逐条呈现"相关要求，新增对输入框 / 气泡视觉规范、表情完整呈现、消息出现动画、以及收发加载态与气泡加载动画（含网络波动下的发送中 / 接收中 / 失败重试反馈）的要求。

## Impact

- **受影响能力规格**：`feixun-messaging`（新增 / 修订若干 Requirement 的行为约定）。
- **受影响代码**：飞讯聊天相关 Flutter 组件——输入栏（`_InputBar`）、气泡（`_MessageRow`）、表情视图（`EmojiView` / `_EmojiPanel`）、会话页（`_ChatViewState`）与消息控制器（`ChatLog`），以及消息发送 / 接收状态模型（新增发送中 / 失败等状态字段）。
- **依赖**：动画使用 Flutter 内置过渡（`AnimatedSwitcher` / `TweenAnimationBuilder` 等），无需新增第三方依赖。
- **数据 / 持久化**：消息模型可能新增"发送状态"字段；需保证旧持久化数据（无该字段）向后兼容，重启后仍可正确恢复。
- **平台**：Windows / Linux / Android 三端一致，动画与加载态在三端表现需统一。
- **破坏性**：无 BREAKING 变更；为既有飞讯模块的增量精修。
